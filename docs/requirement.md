# Android 应用管控需求

状态：已确认。更新日期：2026-10-19。

本文为需求的唯一事实来源，反映需求访谈后的最终决策，不表示功能已经实现或通过实机验证。业务术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 1. 目标与范围

开发 Android 单机应用管控软件，由管理员通过密码管理黑名单及共用周时间表。在限制时段内，阻止黑名单应用被打开、限制其通知，并隐藏其桌面启动入口。

| 项目 | 范围 |
| --- | --- |
| 系统 | Android 11 及以上；使用系统默认桌面 |
| 部署 | 手动安装 APK，通过电脑初始化 Device Owner（完整设备管理身份） |
| 管理范围 | 当前主用户下具有桌面或应用抽屉启动入口的已安装应用，包括符合条件的系统应用 |
| 管理方式 | 本机管理，无服务端、邮件通知或远程管理 |
| 验证范围 | 具体手机型号尚未指定；正式使用前须验证目标设备及其系统桌面，不能仅凭 Android 版本宣称兼容 |

Device Owner 不是普通设备管理员授权。初始化需满足设备注册条件，可能涉及清除账户或恢复出厂设置，应在部署说明中明确。

```text
管理界面：密码验证 → 应用黑名单 / 周时间表 / 总开关 / 设置 / 分类日志
后台管控：首次初始化完成后，总开关 + 周时间表 + 黑名单 → 应用限制或解除
密码文件：首次初始化完成后，只负责管理界面验证，不作为后台管控的运行前提
```

### 1.1 首次初始化

首次初始化须同时完成以下三项：取得 Device Owner 身份、授权密码目录、验证默认密码并完成首次改密。此前只提供初始化引导，不施加本软件的应用和时间管控策略，也不宣称管控已生效。

总开关默认开启表示保存的启用意愿；首次初始化完成后，才按该状态及当前时间执行策略。初始化完成状态独立持久保存，密码删除、损坏、授权失效或密码重新设置不使设备退回首次初始化状态，不因此停止既有管控。后续检测到管理身份或能力异常，按执行失败和权限异常规则处理，不把失败显示为正常管控。

## 2. 密码与管理界面

### 2.1 登录与改密

- 进入管理界面前必须验证密码；首次使用默认密码为 `0000`。
- 默认密码验证通过后，必须设置至少 6 位数字的新密码，才能进入正常管理界面。
- 设置界面允许管理员修改密码。
- 连续输入错误密码 5 次，暂停登录 5 分钟。
- 用户主动切换到其他应用、返回桌面或锁屏后，原登录状态失效，再次进入管理界面须重新验证；在本软件管理页面之间切换不算离开。
- 本软件主动打开的系统目录选择流程属于当前操作的一部分，正常返回不单独使登录失效；流程中发生锁屏、主动切换其他应用或密码文件变化时，仍按相应规则使登录失效。
- 未登录的初始化或密码恢复流程可完成目录选择，但选择器返回本身不授予管理权限，仍须完成相应的密码验证或新密码设置。
- 未登录、登录被暂停或密码存储异常均不停止已有后台管控。

### 2.2 独立密码文件

- 密码校验数据存放在当前主用户的本地共享存储目录，建议初始位置为 `Documents/AndroidManager/password.json`。
- 首次使用通过系统文件选择器授权密码目录访问，并保留目录授权；不使用 `Android/data`、云盘或可移除存储作为密码位置。
- 文件只保存加盐密码校验值，不保存明文密码。黑名单、时间表、总开关及日志与该文件分离保存。
- 用户可通过具有目录访问权限的文件管理器，或经授权的 ADB，直接删除该文件；不设置专门的 ADB 恢复接口，不要求正式 APK 开启调试属性。
- 展示实际密码文件位置。ADB 路径及文件管理器访问能力以目标设备验证结果为准，不承诺所有设备使用同一绝对路径。

### 2.3 密码恢复

| 情况 | 行为 |
| --- | --- |
| 目录可访问，确认密码文件被删除 | 恢复默认密码 `0000`，下次登录后强制改密 |
| 文件损坏、目录不可访问或授权失效 | 提供重新设置入口，允许选择密码目录并设置至少 6 位数字的新密码，不要求旧密码 |
| 进入管理界面或执行管理操作前检测到密码文件变化 | 使当前登录状态失效，重新进行验证或设置 |

重新设置不增加专门的存储修复流程。文件读取异常不自动等同于删除；用户须通过重新设置入口完成恢复。恢复入口不直接开放黑名单、时间表等管理操作。

两种恢复方式均保留黑名单、时间表、总开关和日志，不中断后台管控。共享密码文件在开机首次解锁前可能不可访问，不能据此触发密码重置。

能删除密码文件或使用异常重新设置入口的人可以恢复管理访问权。这是明确保留的恢复方式，不属于防绕过保障；本软件也不承诺抵御已获 ADB 授权或系统特权的使用者。

## 3. 应用列表与黑名单

- 列出当前主用户下具有桌面启动入口的应用，包含可启动的系统市场、浏览器等系统应用；无启动入口的纯后台组件不进入可选范围。
- 支持按应用名称、包名搜索，以及系统应用筛选。
- 管理员可将应用加入黑名单或从中移除。新安装的应用不自动加入黑名单；首次使用黑名单为空。
- 以包名识别应用，保存后的变更立即触发当前策略重新计算。
- 黑名单记录跨应用更新、卸载和同包名重装保留，直到管理员主动移除。应用卸载后显示“未安装”，重装后重新应用当前规则。
- 被本软件隐藏的应用仍保留在管理列表中，不能因当前查询不到启动图标而删除记录或解除黑名单。
- 受保护应用显示不可管控原因，不允许加入黑名单。保护范围包含系统不允许管控的包，以及控制软件自身、当前桌面、输入法等维持管理和设备基本使用能力所必需的应用。
- 受保护状态优先于黑名单。检测到已有黑名单应用变为受保护应用时，保留黑名单记录，标明保护原因，停止对其施加限制并解除本软件已有的限制；保护解除后再按当前规则处理。每次执行策略前须确认其当前保护状态，失败按执行结果记录，不强行绕过保护。

系统应用不等于都能管控。系统市场能否限制，取决于目标设备上该包的系统角色；不可因暂停失败就改用隐藏来绕过系统保护。

## 4. 限制与恢复效果

生效期间，对可管控的黑名单应用执行暂停及隐藏：

- 阻止用户打开该应用，覆盖桌面图标、链接和其他应用跳转等入口。
- 限制开始时已经打开的目标应用也须受到限制，不能继续正常交互使用。
- 限制通知展示，并在已验证的系统桌面中隐藏其启动入口。
- 控制软件自身的入口保持可见。

时段结束、应用从黑名单移除或总开关关闭后，解除本软件施加的暂停及隐藏，恢复应用可用性、保留应用数据，不自动打开应用。

不承诺停止应用的一切后台执行，也不承诺恢复原主屏图标位置、文件夹、固定快捷方式或小组件布局。不采用“发现启动后杀死进程”作为未经验证的兜底方案。

## 5. 共用周时间表

### 5.1 配置与判定

- 全部黑名单应用共用一张每周重复时间表。
- 周一至周日每天最多配置一个时间段，也可不设置；首次使用时间表为空。
- 时间精确到分钟，开始时刻包含在限制内，结束时刻不包含在限制内。
- 开始时间早于结束时间：当天生效；晚于结束时间：延续至次日；相同：不允许保存。
- 跨午夜时间段按开始日归属。次日不设置，不取消前一天延续过来的限制。
- 周日跨午夜可延续至下周一；多个跨日区间重叠时，任一区间有效即保持限制。
- 保存时间表后立即重新计算，不等待下一个周期。

```text
需要限制某应用 = 首次初始化已完成
              且总开关开启
              且应用在黑名单中
              且应用已安装且不受保护
              且当前上海时间落在任一生效区间
```

首次初始化完成后，附加的时间配置限制在总开关开启期间持续生效，不随每日应用限制时段结束而解除。

### 5.2 示例

| 配置 | 结果 |
| --- | --- |
| 周一 09:00–20:00 | 周一 09:00 起限制，20:00 解除 |
| 周一 12:00–09:00，周二不设置 | 周一 12:00 至周二 09:00 持续限制 |
| 周二不设置，周一没有跨日区间 | 周二无应用时段限制 |
| 周三、周四、周五各 10:00–19:00 | 三天分别按各自区间生效 |
| 周日 12:00–09:00 | 延续至下周一 09:00 |

## 6. 总开关与设备时间

### 6.1 总开关

- 默认启用，总开关状态持久保存，重启不改变管理员的选择；首次初始化未完成时该值不代表管控已生效。
- 启用时恢复本软件管控策略，立即按当前时间应用或解除应用限制。
- 关闭时停止新增管控，并解除本软件施加的应用暂停、隐藏及禁止修改时间等附加限制；保留全部设置、日志及管理员密码验证。
- 关闭不主动改动当前日期、时间、时区或恢复启用前的值，只停止强制并允许用户自行修改。
- 关闭总开关保留 Device Owner 身份，因此控制软件仍受该身份固有的卸载限制；关闭不等于退管或允许直接卸载。

### 6.2 时间策略

首次初始化完成且总开关开启时：启用自动校时、关闭自动时区、固定设备时区为 `Asia/Shanghai`，禁止普通用户手动修改日期、时间和时区。

总开关关闭时允许用户修改时间配置；重新启用时恢复上述策略。周时间表始终按上海时区解释。离线时依赖设备时钟继续执行，不以网络连接作为管控前提。

检测到设备日期或时间发生调整（包括自动校时）后，立即依据当前上海时间重新计算限制状态和后续时段边界，不继续沿用调整前的等待计划。重新计算仍遵守初始化状态及总开关，不因时间变化而自行开启管控；该处理不改变日志按设备日期清理的既定规则。

### 6.3 执行失败与开机处理

不增加专门的失败重试流程、失败恢复界面或重试按钮。管理员可重新启用后再关闭，或保持关闭状态重启设备，重新执行解除操作。

保存开关成功不等于系统策略执行成功。实际可观察到的执行失败须记录日志、明确呈现结果或原因，不能把失败应用标为已成功限制或恢复。该要求不引入专门的重试工作流。

```text
开机读取首次初始化状态及总开关
├─ 首次初始化未完成 → 不施加管控
└─ 首次初始化已完成
   ├─ 开启 → 根据当前时间及应用保护状态施加或解除限制
   └─ 关闭 → 执行一次解除本软件遗留限制，然后停止管控

过期日志清理独立执行，不受上述状态影响
```

系统暂停、隐藏和管理员限制可能跨重启保留，因此关闭状态下不能仅跳过策略处理。仅解除本软件施加的策略，不撤销无关系统状态。

## 7. 后台运行与生效要求

- 管控独立于管理界面运行；退出界面、锁屏、未登录和断网均不停止已启用的管控。
- 对已完成首次初始化的设备，开机后无需先登录管理界面，即按已保存配置恢复处理。初始化状态、相关规则、总开关及本软件已有策略记录须在首次解锁前可供后台读取，不依赖共享密码文件；开机执行日志的写入和过期日志清理也须具备首次解锁前的存储访问条件。
- 配置保存、总开关切换、时段边界到达、日期或时间调整以及开机恢复时，立即触发相应策略执行，不主动等待下一时段或下一次重启；应用安装状态或保护状态变化时同样按当前规则处理。
- “立即生效”不附带固定秒数指标，也不表示系统调用、桌面刷新具有零延迟或必然成功的保证。
- 验收须观察目标设备上的实际执行效果；接口拒绝、系统能力不足或图标隐藏不符合要求时，明确该设备或应用的限制，不能宣称全面支持。

## 8. 分类日志

### 8.1 记录与查看

日志仅在管理员登录后查看，支持按类别和日期筛选，不提供手动删除和导出功能。

| 类别 | 记录范围 |
| --- | --- |
| 登录安全 | 密码验证失败，以及可观察到的密码修改、恢复事件 |
| 配置变更 | 黑名单、时间表、总开关等管理配置变更 |
| 管控执行 | 应用限制或解除的执行结果、可观察到的策略执行失败 |
| 权限异常 | 检测到的管理能力、必要权限或密码存储访问异常 |

日志包含事件时间、类别、相关对象、操作及结果，不记录明文密码或密码校验数据。统一按上海时区展示事件时间和划分日期。

不记录重启、关机事件本身；启动后的策略执行结果仍属于管控执行日志。不承诺捕获所有被系统拒绝的启动、卸载、改时间或其他绕过尝试。

### 8.2 文件与清理

- 日志保存在首次解锁前可访问的应用私有存储，与共享密码文件分离；每天一个文件，命名为 `YYYYMMDD.log`，各类别记录写入同一天的文件。存储可访问不代表开放查看入口，界面查看仍要求管理员登录。
- 每次手机启动时清理过期文件，独立于总开关和管理员登录状态。
- 以设备当前时间对应的上海日期为基准；文件名日期早于“当天日期减 90 天”的文件属于超过 90 天，自动删除。
- 不增加日常定时清理任务。长期不重启时，日志可能保留超过 90 天。
- 总开关关闭后修改系统日期可能影响日志归档和下次开机清理范围；不增加可信时间服务或特殊时间异常清理机制。

## 9. 安全边界与不包含的功能

- Device Owner 提供日常防普通卸载能力；本软件不提供一键退管卸载。彻底移除管理属于管理员设备维护，部署说明应说明备份及可能需要恢复出厂设置的流程。
- 本期不管理其他用户、访客、工作资料或应用分身，不承诺这些环境内的管控效果。
- 不保证全部系统应用都可限制，不保证全部后台活动停止，不保证完整审计所有绕过行为。
- 不对密码文件删除、异常重新设置、已授权 ADB、root 或系统特权操作提供防绕过保证。
- 无邮件设置、邮件报警、邮件发送队列、服务端、远程控制或离线恢复码功能。
- 无无障碍拦截兜底、专门的策略失败重试工作流或固定秒数生效承诺。

## 10. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次初始化尚未完成 | 三项条件任一未满足时只显示初始化引导，不施加本软件管控，不将默认开启的总开关显示为已经生效 |
| 首次启动与改密 | `0000` 可验证，必须修改为至少 6 位数字后进入管理界面 |
| 首次初始化完成 | 三项条件完成后保存完成状态，并按已保存总开关及当前规则执行；后续密码恢复不重置该完成状态 |
| 连续错误与重新进入 | 连续错误 5 次暂停登录 5 分钟；主动切换应用、返回桌面或锁屏后须重新验证；管理页面内部切换不退出登录 |
| 系统目录选择流程 | 软件发起的目录选择正常返回不单独退出登录；期间锁屏、主动切换其他应用或密码文件变化仍使登录失效；未登录流程不能借选择器返回直接进入管理界面 |
| 文件管理器或 ADB 删除密码文件 | 确认文件缺失后恢复 `0000`，原规则、总开关和日志不变，管控不中断 |
| 密码文件损坏或授权丢失 | 不自动当作删除；可重新选择目录并设置新密码，不要求旧密码，其他配置不变 |
| 应用列表与保护 | 可启动系统应用可见；纯后台组件不作为可选应用；受保护应用不可加入并说明原因 |
| 黑名单应用变为受保护应用 | 保留黑名单记录，说明保护原因并解除本软件限制；保护解除后按当前规则处理，不强行绕过系统保护 |
| 隐藏、更新及重装 | 隐藏后记录不丢失；更新、卸载重装同包名后仍按原黑名单规则处理 |
| 限制目标应用 | 图标及其他入口不能打开目标应用；已打开应用也受限，通知和桌面入口符合要求 |
| 解除目标应用 | 应用恢复可用、数据保留，不自动打开；不以原桌面布局恢复作为验收条件 |
| 时间段边界 | 同日、跨午夜、跨周及区间重叠均按开始包含、结束不包含处理；相同起止时间不能保存 |
| 不设置的日期 | 无本日新时段，但前一日跨午夜区间仍有效 |
| 自动校时跨越时段边界 | 时间从区间外跳入区间内或反向跳出时，重新计算限制及后续边界；初始化未完成或总开关关闭时不因此开启管控 |
| 保存及开关变更 | 立即触发执行，不等待下一周期；不能只因配置保存就宣称系统策略成功 |
| 总开关关闭 | 解除本软件限制、允许改时间，保留管理密码和配置；Device Owner 身份仍保留 |
| 关闭状态重启 | 再执行一次解除遗留限制，不自动开启管控；原设置仍存在 |
| 已初始化设备开启状态重启、锁屏或断网 | 不依赖管理界面登录，按配置处理；首次解锁前可读取所需私有状态并写入执行日志，共享密码文件暂不可读不使管控失效 |
| 日志查看与文件 | 按四类及日期筛选，文件名符合格式，无密码内容或重启/关机事件记录 |
| 开机清理日志 | 不论总开关状态，首次解锁前可按文件日期删除超过 90 天的日志；不额外运行周期清理任务 |
| 不支持或执行失败 | 不可管控原因或实际失败可见并被记录，不显示虚假的成功状态；无专门重试流程 |
