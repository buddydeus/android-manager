# Android 应用管控技术方案

日期：2026-10-19。状态：方案 A 及分节设计已确认，本文待整体审阅；尚未实现或完成实机验证。

需求唯一事实来源为 [requirement.md](requirement.md)，业务术语见 [GLOSSARY.md](../GLOSSARY.md)。本文规定实现结构、数据契约与验证方法，不扩大需求中的管理范围或防绕过保证。

## 1. 设计目标与选型

实现 Android 11+、当前主用户、Device Owner 模式下的单机应用管控。管理员通过本地密码维护黑名单和共用周时间表；初始化完成后，后台执行与管理登录、共享密码文件及网络连接解耦。

采用方案 A：原生 Kotlin + Jetpack Compose，单个 `app` Gradle 模块，按职责分包。通过接口隔离 Android 系统能力，用纯 Kotlin 实现时间规则和策略计算；使用文件存储，不引入数据库、服务端或多进程。

| 领域 | 选择 | 原因 |
| --- | --- | --- |
| UI | Compose、ViewModel、StateFlow | 管理界面以状态驱动，避免界面直接修改系统策略 |
| 并发 | Coroutines，单进程串行协调器 | 配置保存、系统调用和回执保持一致顺序 |
| 依赖组织 | 构造函数注入，Application 组装依赖 | 当前规模无需额外 DI 框架 |
| 私有状态 | JSON + AtomicFile | 数据规模小，规则和执行记录可作为整体快照保存 |
| 共享密码 | SAF 目录授权 + 独立 JSON 文件 | 满足文件管理器/ADB 删除恢复的要求 |
| 应用管控 | DevicePolicyManager 暂停与隐藏 | 使用设备管理能力执行，保护规则优先 |
| 时间边界 | AlarmManager 单次精确唤醒 | 仅安排下一个有效边界，不使用分钟轮询 |
| 后台事件 | DeviceAdminService 监听 + 短时前台执行服务 | 接收应用变化事件，同时限定执行服务生命周期 |
| 日志 | 按上海日期分文件的 JSON Lines | 对应每日单文件及类别/日期筛选 |

`minSdk=30`。构建工程时选择相互兼容的稳定 Kotlin、AGP、Compose 及 SDK 版本并锁定；不通过降低 targetSdk 回避平台限制。UI/数据分层及单向状态流参考 [Android 架构建议](https://developer.android.com/topic/architecture/recommendations)。

## 2. 结构与职责

```text
app/
├─ ui/                 初始化、登录、应用、时间表、设置、日志
├─ domain/             周时间规则、保护判定、策略计划、结果类型
├─ application/        管理操作、会话校验、串行 PolicyCoordinator
├─ data/               私有状态、SAF 密码、日志、应用元数据缓存
└─ platform/           DPM、包查询、闹钟、系统事件、服务、设备时钟

Compose → ViewModel → 管理操作入口 ───────────────┐
                                              ↓
开机 / 闹钟 / 时间变化 / 包变化 → PolicyCoordinator
                                              ├─ 读取规则和系统现状
                                              ├─ 纯规则计算
                                              ├─ 记录操作意图
                                              ├─ DPM 执行并核验
                                              └─ 保存结果、日志、下一边界

密码仓库 → AuthSession → 管理操作授权
                    后台执行不经过此链路
```

| 组件 | 输入与输出 | 责任边界 |
| --- | --- | --- |
| `ScheduleEvaluator` | 周表、Instant → 当前是否生效、下个边界 | 固定上海时区；不访问 Android API |
| `ProtectedAppResolver` | 当前系统角色和应用信息 → 保护原因集合 | 每轮重新读取，不使用永久静态包名表代替动态角色 |
| `PolicyPlanner` | 配置、应用快照、已有记录 → 目标状态 | 纯计算；保留卸载、隐藏和受保护的黑名单记录 |
| `PolicyCoordinator` | 系统事件/已授权命令 → 执行快照 | 唯一系统策略写入口，处理版本与操作顺序 |
| `DevicePolicyGateway` | 明确目标 → 接口回执及可观察状态 | 包装 DPM、API 版本差异和异常；不自行重试 |
| `StateRepository` | 类型化状态 → 原子读写结果 | 所有状态变更通过协调器串行合并，禁止旧快照覆盖新配置 |
| `PasswordRepository` | 目录 URI → 密码文件状态/验证结果 | 区分缺失、损坏和不可访问；无私有密码备份 |
| `AuthSession` | 凭据验证、生命周期事件 → 内存会话 | 每项管理操作重新检查会话与文件指纹 |
| `AlarmScheduler` | 下个边界/取消 → 调度结果 | 只保留一个 PendingIntent 闹钟 |
| `AuditRepository` | 事件 → 当日日志；日期/类别 → 分页结果 | 串行追加，按启动事件清理，不记录敏感凭据 |

接口使用类型化结果，不用 `Boolean` 同时表达不存在、权限不足和系统调用失败。界面只提交配置意愿并展示回执，不直接调用 DPM。

## 3. 存储与数据契约

### 3.1 存储位置

```text
Device Protected 私有存储（首次解锁前可访问）
├─ state.json                  初始化、配置、策略记录、能力及执行结果
└─ logs/YYYYMMDD.log           当天所有类别的日志

Credential Protected 私有存储（首次解锁后访问）
└─ auth-meta.json              密码目录 URI、登录失败计数及暂停截止信息

当前主用户本地共享存储（SAF）
└─ Documents/AndroidManager/password.json  推荐位置，实际以授权为准
```

启动路径用 `createDeviceProtectedStorageContext()` 构建独立依赖，不初始化 CE 仓库、密码仓库或 UI。开机接收器及相关服务声明 `directBootAware`。不得因共享目录未解锁而判断密码已删除。存储可访问不意味着日志界面无需登录。参见 [Direct Boot](https://developer.android.com/privacy-and-security/direct-boot)。

应用私有数据禁用云备份及设备迁移，避免把别的设备上的初始化状态、DO 操作记录或无效 URI 授权恢复到当前设备。共享密码文件本身仍处于需求明确允许用户操作的目录中。

### 3.2 `state.json`

| 字段 | 类型/约束 | 含义 |
| --- | --- | --- |
| `schemaVersion` | 正整数 | 文件格式版本；未知版本报错，不降级覆盖 |
| `configRevision` | 单调增加的整数 | 已保存管理配置版本；执行回执不增加此版本 |
| `initialized` | Boolean，初始 false | 首次初始化完成标记；密码恢复不改变 |
| `enabled` | Boolean，初始 true | 总开关意愿，不等于实际执行成功 |
| `schedule` | 周一至周日共 7 项 | 每项为 null 或 `{startMinute,endMinute}` |
| `blacklist` | 包名集合 | 更新、卸载、重装及保护状态改变不删除记录 |
| `appCache` | 按包名索引 | 最近名称、系统应用标识、曾有启动入口等展示信息 |
| `policyRecords` | 按包名/设备策略索引 | 调用前状态、操作意图、本软件施加记录及回执 |
| `lastEvaluation` | 版本、时间、结果摘要 | 展示最近执行，不作为下一轮计算的真值 |
| `alarmStatus` | 边界、能力、调度结果 | 调度成功不代表边界已执行；启动时重新核验 |
| `lastCleanupBootCount` | 可空整数 | 同次启动多条启动通知的清理去重标记 |
| `lastPolicyBootCount` | 可空整数 | 开机策略处理去重，与日志清理分别记录 |

分钟范围为 `0..1439`，开始等于结束拒绝保存。时区为代码中的业务常量 `Asia/Shanghai`，不提供可编辑字段。初始黑名单、时间表为空。

`policyRecords` 至少包含：`operationId`、`configRevision`、操作目标、调用前可观察状态、归属证据、`PREPARED/CONFIRMED/FAILED/UNKNOWN`、逐步骤结果及最近错误。黑名单删除不删除尚未解除的策略记录；确认本软件策略已解除后才可压缩该记录。

配置文件使用 AtomicFile 的完整写入流程，异常调用 `failWrite`。AtomicFile 不提供互斥，所有读取后修改操作仍受同一串行入口约束。首次建立空状态只发生在确认全新安装的初始化路径；已有文件损坏、未知版本或初始化证据与文件缺失冲突时进入存储异常，不能静默新建空黑名单或批量解除系统限制。参见 [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)。

### 3.3 密码文件

`password.json` 字段：`schemaVersion`、`kdf`、`iterations`、Base64 `salt`、Base64 `verifier`。不包含黑名单、总开关、日志或明文 PIN。

- 使用 `PBKDF2WithHmacSHA256`，随机 16 字节盐、256 位校验值，首版采用 600,000 次迭代。在工作线程计算，以常量时间比较校验值。
- 首版只接受已支持的格式和固定参数，检查字段长度、Base64 长度及文件大小上限，不能直接执行外部文件指定的任意算法或迭代次数。
- 普通密码为至少 6 位 ASCII 数字；`0000` 只用于首次初始化或确认文件被删除后的默认验证，验证后仅获得“必须改密”状态。
- 默认验证状态可在内存中表示，不必先向磁盘写入一份默认密码文件；完成新密码写入并回读验证后才授予管理会话。
- 验证所需数据只在当前操作内使用，不存入私有文件、日志、SavedStateHandle 或备份；密码字段显示及异常消息均须脱敏。

算法在目标最低版本可用，参见 [SecretKeyFactory](https://developer.android.com/reference/javax/crypto/SecretKeyFactory)。迭代参数参考 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，并须测试目标设备的登录耗时；文件删除恢复是既定产品机制，KDF 不改变这一安全边界。

### 3.4 SAF 授权与写入

通过 `ACTION_OPEN_DOCUMENT_TREE` 授权，并持久保留读写 URI 权限。仅接受系统本地外部存储提供者的主共享存储目录，排除云提供者、可移除卷、`Android/data` 及系统不允许的目录。推荐初始目录仅是选择提示，实际 URI、显示路径及读写能力均须验证；不能把 URI 任意拼接为文件路径。参见 [SAF 文档访问](https://developer.android.com/training/data-storage/shared/documents-files)。

读取返回五种状态：`READY`、`MISSING`、`CORRUPT`、`ACCESS_DENIED`、`IO_ERROR`。只有成功列举已授权目录且确认固定文件名不存在时才返回 `MISSING`；查询失败或无法读取不等于删除。重复同名文档按异常处理，不随意挑选一个验证。

写入前在内存构建完整内容，写后关闭流、重新读取并验证。修改已有文件使用支持截断的写模式，不先删除旧文件。SAF 提供者不保证 AtomicFile 式原子替换，不能把本地文件重命名语义套到 `content://` URI；中断造成损坏时走既定密码恢复入口。选择新目录时，先完成新文件验证，再保存目录元数据；任何失败都不授予会话。参见 [ContentResolver 文件访问](https://developer.android.com/reference/android/content/ContentResolver)。

## 4. 初始化、认证与会话

```text
首次启动
  → 检查 Device Owner
  → 授权密码目录
  → 验证 0000
  → 写入并验证新 PIN
  → 原子保存 initialized=true
  → 按 enabled 和当前时间执行策略

后续进入
  ├─ 文件正常 → 验证 PIN → 管理会话
  ├─ 确认缺失 → 验证 0000 → 强制新 PIN → 管理会话
  └─ 损坏/访问异常 → 重新选择目录及设置新 PIN → 管理会话

任一认证路径失败：不进入管理界面；已有后台管控继续
```

初始化中途退出后从已完成步骤继续：若新 PIN 已成功写入但完成标记尚未保存，应验证现有新 PIN 后继续，不能用默认密码覆盖。只有 DO、目录访问及新 PIN 三项同时满足才提交完成标记。精确闹钟等额外能力单独展示，不改变需求规定的三项初始化条件，也不能在能力缺失时显示“全部正常”。

连续错误 5 次暂停登录 5 分钟。计数和暂停信息持久保存，成功验证后清零；重启应用及简单重建页面不清零。同一次手机启动使用 `elapsedRealtime` 计算暂停剩余时间；跨重启按持久化的设备时间截止值恢复并将剩余值约束在 0 至 5 分钟。它不构成可信时间或防系统特权绕过机制。参见 [SystemClock](https://developer.android.com/reference/android/os/SystemClock)。

管理会话仅存内存，包含随机会话 ID、已验证密码文件内容指纹及失效状态。旋转等配置变化可保留进程内会话，进程死亡必须重新登录。管理操作在执行入口检查会话及当前完整文件指纹，不能只比较文件大小和修改时间。发现删除、改变或访问异常即失效，再进入对应认证路径。

使用 Activity 生命周期、用户离开提示及锁屏状态共同处理失效：主动 Home/切换其他应用即清除会话，锁屏事件清除会话，回到前台再次核验；应用内导航不清除。不要仅依赖带延迟的进程后台通知。外部文件操作与本应用无法建立跨进程事务，文件检查之后发生的并发修改在下一次检查失效，不宣称消除所有竞争窗口。生命周期依据见 [Activity 生命周期](https://developer.android.com/guide/components/activities/activity-lifecycle)。

目录选择只出现在未登录的初始化/恢复流程；正常改密直接更新已授权文件，不新增已登录的目录迁移功能。目录选择正常返回不会额外失效，但也不会产生管理会话；锁屏、切换或文件变化后必须重新完成相应验证/设置步骤。由此无需为识别系统选择器期间的跨应用行为增加 Usage Access 或无障碍权限。

登录成功后所有管理页面受统一入口保护，日志读取也受保护。后台事件入口只能触发重算，不能借 Intent 参数直接修改密码、黑名单或总开关。

## 5. 应用清单与保护规则

应用目录以当前主用户下可解析 `ACTION_MAIN + CATEGORY_LAUNCHER` 的包去重，包含第三方和系统应用；声明相应包可见性能力。展示列表为“当前可启动应用 ∪ 黑名单 ∪ 尚有本软件策略记录的应用”，避免隐藏后记录消失。图标按需加载，名称缓存只用于展示。

状态区分 `INSTALLED`、`HIDDEN_BY_US`、`UNINSTALLED`、`UNKNOWN`；查询不到启动 Activity 不能直接等同于卸载。结合包事件、PackageManager 和 DPM 隐藏状态判断。`MATCH_UNINSTALLED_PACKAGES` 可能包含已卸载保留数据或归档条目，不能单独证明应用仍安装。无法确认时显示未知，保留记录并记录查询异常。参见 [PackageManager](https://developer.android.com/reference/android/content/pm/PackageManager)。

保护判定包括：本软件、系统当前桌面、输入法及其他维持基本使用的角色，以及系统明确禁止暂停/隐藏的应用。动态解析桌面、已启用输入法、默认拨号等角色；对安装器、卸载器、权限控制等关键系统角色采取保守保护。角色无法可靠解析时标记能力异常，不尝试强制隐藏。

每轮执行前刷新保护状态，单包变更前再检查一次。黑名单中的包变为受保护时，保留黑名单并解除本软件已有策略；保护状态消失后按现有规则重新计算。系统拒绝暂停必须保留拒绝结果，不能改为“仅隐藏”绕过保护。具体系统能力以 [DPM 应用暂停说明](https://developer.android.com/work/dpc/security#suspend-apps) 为依据。

包更新事件使用 `EXTRA_REPLACING` 区分短暂移除与真正卸载。卸载保留包名规则，清除失效的运行状态证据；同包名重装重新获取安装实例和保护状态，重新建立策略记录，不把上一次安装的成功回执当作当前成功。

## 6. 时间规则与闹钟

### 6.1 纯规则算法

以注入的 `Clock` 获取 Instant，转换为 `Asia/Shanghai` 的日期时间。对于每个开始日生成 `[start,end)`：结束分钟小于开始分钟时结束日加一天；相同值在输入层拒绝。

当前判定只需检查今天及昨天开始的区间。下一边界计算展开昨天至未来 7 天的开始日，合并重叠或首尾相接的区间，再取严格晚于当前时刻的第一个状态变化点。空时间表返回未限制及无下个边界；时段归属由开始日期决定，不受次日空配置影响。

```text
周一 12:00 ────────────── 周二 09:00
                     周二 08:00 ───── 周二 10:00
合并：周一 12:00 ──────────────────── 周二 10:00
      开始限制                        解除
```

规则结果与总开关分离：只有 `initialized && enabled` 才使用周表施加应用策略。时间配置限制覆盖整个启用期间，不随应用时段结束而释放。

### 6.2 单次边界调度

使用显式、不可变的广播 PendingIntent 与 `RTC_WAKEUP`，通过 `setExactAndAllowWhileIdle` 安排下个有效边界。每次配置变化、时间变化、开机及事件执行后都更新调度；关闭或初始化未完成时取消。使用固定 PendingIntent 身份替换旧闹钟，不保存一周的独立闹钟列表。

API 31+ 每次安排前检查 `canScheduleExactAlarms()`；能力不存在或调用抛出异常时记录并展示“定时执行不可用”，继续处理当次已触发的策略，不静默换成非精确调度。权限授予事件触发重算；权限撤销可能终止进程并取消闹钟，重新启动、服务绑定及前台进入时均重新检查。参见 [精确闹钟机制](https://developer.android.com/develop/background-work/services/alarms)。

允许空闲时执行的精确闹钟仍受系统节流和调度限制，不能保证相邻一分钟的边界在深度休眠时都准点送达。事件到达后立即重算当前状态，不能按旧闹钟携带的“开始/结束”指令机械执行。密集边界、Doze 及 OEM 电源管理须实机验证；不能用业务“立即”承诺零平台延迟。参见 [AlarmManager](https://developer.android.com/reference/android/app/AlarmManager)。

## 7. 事件接入与后台生命周期

### 7.1 事件来源

| 事件 | 接入方式 | 行为 |
| --- | --- | --- |
| 配置保存、总开关变化 | 受认证保护的应用命令 | 持久保存后立即提交重算 |
| `LOCKED_BOOT_COMPLETED` | Direct Boot 接收器 | 清理过期日志，读取 DP 状态，恢复/解除策略并安排边界 |
| `BOOT_COMPLETED`、`USER_UNLOCKED` | 接收器 | 补全解锁后应用信息及能力检查；不重复记录重启事件 |
| 下一时间边界 | 显式 AlarmReceiver | 读取最新规则和当前时间重算 |
| `TIME_SET`、`TIMEZONE_CHANGED`、日期变化 | 系统广播 | 重新计算，必要时纠正启用状态下的时间设置 |
| 包安装、更新、卸载、组件变化 | 运行时包事件接收器 | 更新目录并重算；更新过程合并为当前状态读取 |
| 桌面、输入法、默认角色变化 | 对应系统通知/设置观察 | 刷新保护判定；每次策略执行仍重新解析角色 |
| 本软件更新、管理能力变化 | 自身包更新/管理回调 | 重新加载状态、检查身份与能力、重建监听及闹钟 |
| 管理页面进入、事件服务重新创建 | 本地生命周期事件 | 刷新能力与当前状态，补偿进程不在时的事件缺口 |

包事件接收器单独使用 `package` data scheme；不能给开机/时间接收器共用该过滤条件。接收器仅验证来源、归并触发并移交任务，不在 `onReceive` 主线程遍历应用或写大量文件。

### 7.2 DeviceAdminService 与执行服务

不能假定静态声明 `PACKAGE_ADDED/REPLACED` 就能在进程不存活时接收到所有事件。启用管控时启用 `DeviceAdminService` 组件，声明 `ACTION_DEVICE_ADMIN_SERVICE` 和 `BIND_DEVICE_ADMIN` 绑定权限，由系统绑定；服务动态注册包广播、角色相关通知及必要的设置观察。此组件只维持事件接收，不轮询应用启动或时间。

这是对短时执行服务方案的必要补充：没有可靠事件接入，黑名单应用重装后可能一直等到下个时段边界才被限制。系统可能在内存紧张时回收该进程，之后重新绑定；服务创建时提交一次当前状态重算，不假设每条历史广播都能补发。官方行为见 [DeviceAdminService](https://developer.android.com/reference/android/app/admin/DeviceAdminService)。

`PolicyExecutionService` 只承担当前一轮或已合并事件的策略执行，执行期间发出前台通知，结束后释放资源并停止。Android 14+ 采用符合 DO 身份的 `systemExempted` 前台服务类型及对应权限；更低版本走相应 API 路径。这里“短时”描述生命周期，不使用平台的 `shortService` 类型。启动失败单独记录，不假设 DO 能绕过所有 OEM 限制。参见 [前台服务启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) 与 [systemExempted 类型](https://developer.android.com/develop/background-work/services/fgs/service-types#system-exempted)。

只有实际执行时使用有超时保护的短期 CPU 唤醒锁，任务结束在 `finally` 释放；不能用长期持锁维持定时。关闭总开关时先保存关闭意愿，取消闹钟，执行一次解除并结束前台服务，然后禁用事件服务组件及动态监听。开机接收器始终可用，以便关闭状态下清理遗留策略和过期日志；关闭不撤销 DO 身份。

事件服务组件默认禁用，初始化完成且总开关开启后启用。每次服务创建及开机按持久配置纠正组件状态，处理保存配置后、切换组件前的进程中断。开机策略去重独立于日志清理：关闭状态已在解锁前完成一轮处理，则解锁通知不额外重复解除；若解锁前通知未送达，后续启动通知补执行。开启状态在解锁后可因应用信息变完整重新计算。

```text
系统事件 → 校验/合并触发 → 启动执行服务
                              ↓
                       串行计算并执行
                              ↓
                    保存结果、安排下一边界
                              ↓
                       停止执行服务

启用期间：DeviceAdminService 保留事件监听
关闭期间：无持续管控监听；保留开机处理与管理入口
```

## 8. 策略执行、归属与崩溃一致性

### 8.1 串行协调流程

1. 读取最新完整状态；状态异常时停止新增操作并显示错误，不用空配置替换。
2. 检查 DO 身份、当前主用户、实际时间、安装状态及保护状态。
3. 初始化未完成则取消调度、不施加策略；关闭状态生成解除本软件遗留策略的计划；开启状态生成时间策略与应用策略计划。
4. 在系统调用前持久记录操作意图和已有归属证据。该写入失败则不发起新的系统变更。
5. 逐步骤执行，保存回执、可观察状态及日志。单包失败不阻断其他包，也不阻止独立的解除或闹钟安排。
6. 读取当前时间及最新配置版本，安排下一边界。执行期间若已跨边界或收到更新触发，立即进入下一轮当前状态计算。

配置变更和系统变更共享串行入口；新命令等待正在进行的单个系统调用结束，不能并行发出相互冲突的隐藏/恢复指令。事件可合并，但不能丢弃已保存的新配置。执行自产生的包/时间通知仅引发核验；状态已匹配时不重复调用，以免形成反馈循环。

### 8.2 单包操作顺序

```text
需要限制：确认可管控 → 暂停 → 核验暂停回执 → 隐藏 → 核验隐藏回执
需要解除：确认本软件归属 → 解除隐藏 → 解除暂停 → 核验各项结果
```

调用 `setPackagesSuspended` 检查返回的失败包名，调用 `setApplicationHidden` 检查返回值并在可查询时核验。已隐藏时若暂停查询不可用，保留最近的本软件回执和未知项，不把查询失败当作暂停已解除。接口、限制及时间设置参考 [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager)。

暂停失败不继续隐藏。暂停成功而隐藏失败属于部分成功，保留暂停效果并显示细分结果，不做自动回滚。解除隐藏失败仍可尝试解除本软件暂停，两项结果分别记录。只有满足全部目标且证据充分时显示完整成功。

### 8.3 归属记录与中断

执行前记录本管理员已有状态和聚合可观察状态。聚合“已暂停/已隐藏”不能证明由本软件施加；已有无归属的限制保持不动，并展示外部状态或归属未知。本软件只解除有自身调用记录或管理员专属查询证据支持的策略。

操作日志采用“先意图、后回执”，不声称与系统服务构成原子事务。若调用后进程死亡、回执未写入，下次普通触发读取 `PREPARED` 记录并核验现状：能证明归属和结果则补记；不能证明则标为 `UNKNOWN`，不通过盲目解除来猜测。具有本软件归属证据的未完成目标按当前意愿重新核对执行，不回放过期限制命令。

不增加独立重试队列、退避任务、自动回滚或重试按钮。配置/系统事件、服务恢复、管理员开关操作及开机属于既有重算入口；它们可再次处理当前状态，但不承诺修复所有系统拒绝或归属不明情形。

### 8.4 时间策略

启用时依次确保自动校时开启、自动时区关闭、时区为 `Asia/Shanghai`，再施加禁止配置日期/时间的用户限制；按 API 版本使用对应 DPM 接口。每步单独记录，时区设置失败不能把整组显示成功。

关闭时仅清除本管理员施加的禁止修改限制，不调用“恢复旧时间/旧时区/旧自动设置”的操作；下次启用重新确保目标值。管理员限制的读取与清除必须使用与该 Android 版本相同的本地/全局策略范围，不能用 UserManager 的聚合限制推断本软件归属。其他系统限制仍存在时显示其影响，不保证普通用户立即可修改。

## 9. 日志与界面状态

每行日志是独立 JSON 对象：`eventId`、`occurredAt`、`category`、`action`、可选 `packageName`、`configRevision`、`result`、脱敏 `reasonCode/message`。事件时间保存带偏移的上海时间；分类固定为登录安全、配置变更、管控执行、权限异常，禁止写入 PIN、盐、校验值或密码文件完整内容。

按事件发生时的上海日期选择 `YYYYMMDD.log`，多类别同文件，串行追加。读取采用逐行解析与分页，尾部因崩溃产生的不完整行跳过并提示；写入前修复必要的行分隔，避免下一条记录粘接在残缺行后。写入失败不递归写同一日志，改由执行快照/内存错误状态展示可观察的存储异常。

每次手机启动执行日志清理，不依赖登录或总开关；只删除符合严格文件名格式且日期 `< 当天上海日期.minusDays(90)` 的日志。正好 90 天的文件保留，非法文件名不删除，不扫描其他目录。`LOCKED_BOOT_COMPLETED` 与后续启动通知可用系统启动计数去重；读取计数失败时允许幂等重复检查。清理失败保留文件并记录可观察异常，不新建日常清理任务。启动计数依据见 [Settings.Global.BOOT_COUNT](https://developer.android.com/reference/android/provider/Settings.Global#BOOT_COUNT)。

不记录开机/关机事件本身。启动引发的真实策略执行结果可以记录；重复的无变化核验不生成大量成功日志。时间调整可能使日志日期倒退或影响清理范围，按需求使用设备时间，不新增可信时间服务。

界面信息结构：

```text
初始化 / 登录 / 密码恢复
           ↓
主界面：总开关意愿、当前时段、执行状态及能力异常
├─ 应用：名称/包名搜索、系统筛选、黑名单、保护原因、实际结果
├─ 时间表：周一至周日、单段/不设置、跨日提示
├─ 设置：改密、实际密码文件位置、能力状态
└─ 日志：日期、类别、分页记录
```

保存成功先显示“已保存，正在应用”，执行后显示完整成功、部分成功、失败或未知。关闭意愿已保存但仍有解除失败时显示“已关闭，存在未解除限制”。不将未安装、受保护、系统拒绝、隐藏失败合并为同一种状态，不用重试按钮掩盖能力问题。

## 10. 权限、组件与部署

| 项目 | 用途与约束 |
| --- | --- |
| DeviceAdminReceiver | 系统 DO 注册入口，受 `BIND_DEVICE_ADMIN` 保护；普通设备管理员身份不算完成 |
| DeviceAdminService | 同样受系统绑定权限保护，启用时负责事件监听 |
| `RECEIVE_BOOT_COMPLETED` | 解锁前后启动恢复及日志清理 |
| `QUERY_ALL_PACKAGES` | 设备管理场景的完整应用可见性；结果仍按业务范围筛选 |
| `SCHEDULE_EXACT_ALARM` | 按系统版本检查特殊访问能力；不假定声明即授权 |
| `FOREGROUND_SERVICE` | 执行期间前台服务 |
| `FOREGROUND_SERVICE_SYSTEM_EXEMPTED` | API 34+ 对应 DO 执行服务类型 |
| `POST_NOTIFICATIONS` | API 33+ 前台通知展示按系统权限处理；拒绝不等同于解除系统策略 |
| `WAKE_LOCK` | 单次执行期间短时 CPU 保持，必须超时及释放 |
| SAF 持久目录授权 | 密码文件访问；不申请所有文件访问权限 |

所有内部管理组件不导出；必须供系统访问的组件明确声明权限与允许来源。闹钟使用显式不可变 PendingIntent，系统事件只读取系统现状，外部输入不能携带任意待执行包操作。发布 APK 不启用调试，不提供外部重置命令、无障碍服务、使用情况访问或进程杀死兜底。

部署交付应记录 APK 签名、包名、管理组件、系统版本和实机验证结果，并提供真实组件名对应的 DO 初始化说明。注册前验证账户、用户及设备注册条件，说明可能需要恢复出厂设置；不能承诺所有在用手机直接注册。后续升级使用相同签名及包名，不通过卸载重装更新控制软件。关闭总开关不退管，无一键卸载；管理员维护须说明数据备份及清除设备的影响。

### 11.2 组件与故障注入

- 在保存配置前后、写入操作意图后、每个系统调用后、回执保存前终止流程，验证不会虚报成功、丢失黑名单或盲目解除外部策略。

- 验证外部密码文件变化、5 次错误暂停、进程重建、Home/切换/锁屏、目录选择与恢复入口权限隔离。
- 注入暂停失败、隐藏失败、部分解除失败、安装状态未知、角色变化及重复系统事件，验证逐项结果与无反馈循环。
- 模拟配置执行中更新、时间边界跨越、陈旧闹钟、精确闹钟授权变化及服务启动失败，验证按最新状态处理。
- 在关闭状态重启及 CE 不可用条件下验证 DP 依赖链、残留解除、日志写入和清理。

### 11.3 目标设备验收

以需求第 10 节为最终验收清单，至少覆盖最低 Android 11 与实际交付版本；涉及 API 31、33、34+ 的能力差异分别验证。模拟器只能辅助，不能替代目标 ROM 与系统桌面测试。

| 关键验证 | 通过条件 |
| --- | --- |
| 系统市场及普通应用 | 限制前已打开的界面不能继续使用；桌面、链接、跨应用跳转及通知效果符合需求 |
| 隐藏与解除 | 图标消失、管理记录保留、解除后可用且数据保留；不要求原布局复原 |

| 闹钟与 Doze | 长时间锁屏、断网、相邻短间隔边界、时间跳变时测量实际结果，不只看 API 返回 |
