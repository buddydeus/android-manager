# TOTP登录实施草案

状态：基于用户明确的无固定密码目标；用户已选择服务器命令初始化；生产切换须待真实身份验证器确认。

流程：

```text
现有账号 → 安全领取绑定密钥 → 身份验证器生成验证码
                                    ↓ 验证成功
                     保存TOTP身份、撤销旧会话、停用密码
                                    ↓
                           用户名 + TOTP登录
```

沿用Fastify/Vue/SQLite及现有会话、Cookie/CSRF。服务端独立模块实现RFC6238算法并用官方测试向量验证；使用Node加密能力，二维码如需新依赖另行核对现有能力。密钥以服务端独立加密密钥保护，数据库保存带版本密文；加密密钥存储于数据卷独立权限600的auth.key，不进入数据库文件或构建包；完整私有备份复制该文件，恢复时二者配套。密钥缺失或解密失败必须停止鉴权，不能自动重建管理员或退回密码。

候选密钥与激活身份分开；绑定验证前旧身份保持有效。激活事务检查身份版本、消费验证码时间步、切换身份并撤销旧会话。新登录事务原子消费时间步与创建会话，防止并发重放；错误/过期/已用验证码统一失败。持久化限速不随重启清除，结合账号、来源及有限冷却。

需要覆盖：RFC向量、边界/容差/重放/并发/重启、绑定失败不锁定、成功停用密码、旧会话失效、密钥缺失及备份恢复、限速持久化、网页绑定和新登录、设备鉴权不受影响。通过独立审查和隔离测试后部署；用户完成真实身份验证器绑定验证，才完成生产切换。

依据：https://www.rfc-editor.org/rfc/rfc6238

命令采用prepare（生成本地私密资料不改库）→activate（先验证手持验证码，再绑定、撤销旧会话），正式切换无需旧密码。新部署init→confirm；reset→confirm仅供服务器管理员恢复。SQLite v4增auth_attempts；限速账号5次/IP20次、5分钟窗口。此为单因素动态码身份，不声称防钓鱼或多因素认证。
