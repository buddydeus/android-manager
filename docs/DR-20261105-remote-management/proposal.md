# DR-20261105-remote-management 技术方案

日期：2026-11-05。状态：**已整体批准，实施中；当前会话实现、独立子代理审查**。

需求来源：[requirement.md](requirement.md)，已确认 B1–B27、未决为无。既有本机规则见 [原技术契约](../proposal.md)，术语见 [GLOSSARY](../../GLOSSARY.md)。本文只扩展远程管理相关边界，不替代无关本机功能。

用户已选择 **TypeScript：Fastify + Vue + SQLite**；下面未由用户逐项指定的协议、超时、数据结构及部署组织是本方案的技术建议，随本文整体批准，不伪称先前已确认。

## 1. 路线与交付范围

| 路线 | 取舍 | 结论 |
| --- | --- | --- |
| TypeScript / Fastify / Vue / SQLite | 服务端与网页共用语言和契约，单机部署组件少 | 用户已选择 |
| Kotlin / Ktor / Vue / SQLite | 服务端沿用 Android 语言，网页仍需独立工具链 | 未选择 |
| Java / Spring Boot / Vue / PostgreSQL | Java 运维工具丰富，增加数据库服务与部署成本 | 未选择 |

- Android 继续使用 Kotlin / Compose，最低 Android 11、target SDK 36；保留单 `app` 模块和既有五层职责。
- 服务端采用 Node.js 24 LTS、Fastify 5、TypeScript、Zod 输入契约、better-sqlite3；网页采用 Vue 3、Vite、TypeScript。实际兼容补丁版本在实现时核验后锁定，不使用浮动生产依赖，运行时选择遵循 [Node LTS](https://nodejs.org/en/about/previous-releases) 与 [Fastify 支持策略](https://fastify.dev/docs/latest/Reference/LTS/)。
- Android 网络采用 OkHttp 的 HTTPS / WSS；本地新增统计和命令存储采用系统 SQLiteOpenHelper，保留现有 AtomicFile 配置，避免把既有策略状态全部迁移到新库。
- 单服务实例加本机 SQLite WAL；不引入 Redis、消息中间件、Google 推送或多租户。数据库只放本机持久卷，不放网络文件系统。SQLite 的单写者和 WAL 同主机约束见[官方说明](https://www.sqlite.org/wal.html)。
- 交付包含 Android 改动、服务端、网页、容器和运维说明、自动化验证及设备验证记录。实际生产部署需要服务器访问权、DNS/TLS 与正式签名材料，不能把本地构建称为已部署。

这是跨 Android、服务端与网页的项目级改动。方案批准前不安装依赖、搭建产品脚手架或改产品代码。

## 3. 身份、固定地址与初始化

### 3.1 网页管理员

部署时通过服务端 CLI 创建唯一管理员，不提供公网注册、默认密码或多用户角色管理。密码使用带独立盐的 scrypt，参数和版本随摘要保存；账号与密码不写仓库。登录采用随机服务端会话，Cookie 为 `Secure / HttpOnly / SameSite=Strict`，空闲30分钟、最长12小时失效，注销即撤销。

写操作校验 CSRF token 与 Origin；登录限速，错误不泄露账号是否存在。管理 API 与设备 API 鉴权分离，设备凭据无权登录网页或选择其他设备。内部错误脱敏，日志不包含密码、注册凭据、会话或设备 token。

### 3.2 自动注册

App 构建时固定 HTTPS 原点 `https://ams.opt.work`，仅访问该原点的协议路径；release 禁止明文 HTTP、任意证书信任及跨原点下载重定向。注册接入凭据由部署环境注入受控安装包，不提交源码；它不是设备硬件真实性证明，被提取后可能被用于注册新设备，部署者须限制安装包与凭据分发。每台已接入设备仍使用独立凭据，泄露一台设备 token 不应获得其他设备权限。

```text
initialized=false → 保留现有初始化，不自动注册、不执行远端命令
initialized=true
  → 创建并持久保存 installId 与本机密钥标识
  → 取得一次性服务端挑战
  → 接入凭据 + 公钥 + 挑战签名注册
  → 服务端分配 deviceId / 随机设备 token
  → 原子保存身份 → 首次上传本机配置 → 允许网页编辑
```

密钥建议 AndroidKeyStore P-256，禁用用户交互认证要求；身份元数据和设备 token 放 DP 私有存储。注册挑战两分钟失效、单次使用；服务端对接入凭据和 token 只保存摘要，公钥用于证明同一安装身份。注册恢复按 installId + 公钥去重，响应丢失时重新签名挑战可重发新的设备 token；不得创建重复设备或重置其现有配置。同 installId 但公钥不同直接拒绝。

正常重连只用设备 token；注册恢复才使用接入凭据与挑战。私钥丢失不能假装原设备，报告身份异常，交由管理员维护；不为恢复连接自动清配置、清应用数据或重新取得 DO。

注册字段只发送安装身份、设备型号、Android/API版本、App版本及能力状态，不读取 IMEI、联系人或账号。私有备份继续禁用。首次解锁前可使用所选 Keystore 配置是设备能力验证项；若目标 ROM 拒绝，报告远程身份暂不可用并在解锁后恢复，本地 DP 管控照常。

### 3.3 本机认证边界

本机会话及 generation 校验维持原样。远程请求经过独立设备身份、消息类型、设备目标、版本与重放校验，转换为不可由外部 Intent 构造的已鉴权命令。

PolicyCoordinator 仍是配置和系统变更唯一串行入口；网络和安装包下载在其锁外运行，提交时重新检查身份及命令状态。远程配置不复用本机登录会话，不读取 SAF 密码，不开放任意执行脚本或系统调用入口。

## 4. 配置同步与时间契约

### 4.1 同步对象

`ConfigSnapshot = { enabled, blacklist, schedule[7] }`；黑名单为去重包名集合，周表仍为每天 null 或 `{startMinute,endMinute}`。验证分钟范围、起止不等、包名格式和容量，保护包由设备根据当前角色再次核验。未知应用不假装已安装；保留既有卸载黑名单的展示语义。

每份配置伴随 `mutationId / modifiedAtMs / timeQuality / origin`，服务端另分配单调 `serverRevision`。`serverRevision` 用于传输去重和回执关联，**不作为冲突优先级**；设备原 `configRevision` 仍是本地保存版本，不与服务器版本混用。

初次升级旧数据时若没有修改时间，以首次接入创建的本机基线建立同步对象，标记 `origin=MIGRATED_BASELINE`；这不是历史修改时间的推断。服务端必须接收基线成功后才开放该设备配置编辑；重新注册身份不能重复覆盖已有服务端配置。

### 4.2 更新时间

网页保存时间由服务器在保存入口采集，设备本机保存时间由下述时钟估算，均为 UTC 毫秒。展示及周表解释仍采用 Asia/Shanghai。

1. 通过鉴权时间接口记录请求发出/收到的单调时间和服务器时间，估计服务器与本机偏差及往返误差；异常高时延样本不替换更可靠的近期样本。
2. 同一次系统启动内，以“最近服务端时间锚点 + elapsedRealtime 增量”产生后续修改时间，避免手动改时钟影响；断网继续沿用锚点。
3. 重启导致单调时钟归零后，以持久偏差和设备墙钟暂估，标记 `ESTIMATED_AFTER_BOOT`；尚无锚点则标记 `UNCALIBRATED`。联网取得新锚点只影响后续修改，不能给既有离线修改重新打上当前时间。
4. 不偷偷截断或重排已保存的时间来偏向某一端；异常时钟质量在同步结果中可见。离线重启后的先后误判属于已确认限制。

系统墙钟可跳变、elapsedRealtime 包含休眠的定义见 [SystemClock](https://developer.android.com/reference/android/os/SystemClock)。

### 4.3 保存、比较与崩溃恢复

```text
本机保存
 → 同一 AtomicFile 写入配置 + mutationId + 更新时间 + 待同步标记
 → 立即按既有策略执行
 → 网络 worker 发送候选（无网络则保留）

服务器事务比较候选与当前配置
 ├─ 候选较新 → 整份替换，增加 serverRevision
 ├─ 候选较旧 → 保留当前配置，返回当前快照
 └─ 时间相同 → 保留当前服务端版本
 → 同事务保存结果与可重发的配置变更通知
```

设备收到响应或推送后回到同一协调入口重新读取当前状态：若请求期间又有新的本机修改，不使用旧响应清除其待同步标记；响应中的服务端快照也须与当前本机候选比较，时间相同则服务端胜。较新的本机候选继续上传；远端胜出则原子替换同步字段和来源元数据，保留初始化、DPM归属回执、密码目录等本设备状态。

网页多个请求的实际保存时刻由服务器决定，事务选择仍用相同时间规则。相同 mutationId 重传返回已记录的接收结果，并附上查询时最新的服务端配置，不新增版本或复活历史快照；同 ID 不同内容拒绝。任何一端的接收/执行回执均不产生新的修改时间，不造成同步回环。相同 mutationId、内容和来源元数据的重复下发只更新传输回执，不重复修改本地配置版本。

重连先做一次携带本地待同步候选的双向同步，**不能先无条件拉取覆盖本机再上传**。配置推送仅通知版本有变化，实际通过鉴权 HTTPS 同步取得快照；遗漏通知不丢已持久化配置。

网页区分“已保存到服务器 / 待设备同步 / 已保存到设备 / 策略执行成功、部分失败或未知”。回执携带配置 mutationId、服务端版本和设备本地版本，不能将旧回执显示为当前配置结果。

## 5. 生命周期与推送

当前 `events(s.enabled)` 改为初始化完成且具备 DO 时维持 DeviceAdminService；管控策略是否启用仍由 enabled 判定。服务持有网络连接协调器和使用事件监听，不持有 Activity，不触碰 credentials 懒加载字段。

- DeviceAdminService 负责 WSS 与网络回调、屏幕事件及现有应用目录事件；PolicyExecutionService 仍只执行有限任务，结束即停止。DO 系统绑定的能力边界见 [DeviceAdminService](https://developer.android.com/reference/android/app/admin/DeviceAdminService)。
- 每条连接获得随机 connectionId；设备每30秒提交轻量心跳，服务端90秒未收到或连接断开即标记离线。心跳是连接健康检查，不是轮询应用启动或周表。
- 断线使用带随机扰动的退避（1秒至5分钟），只在网络可用且服务存活时调度；网络恢复、服务重建、开机和自身升级后立即尝试恢复。无网络时停止空转；不长期持唤醒锁，不依赖精确闹钟保活。
- 配置、统计、目录和升级任务通过 HTTPS 持久化及恢复；WSS 丢失可由重连补齐。系统/OEM 可以延迟重连，不宣称常在线。
- 开机路径恢复身份、最后系统启动状态和队列，CE/UsageStats 未解锁时跳过历史补查；本地策略仍按原 Direct Boot 契约执行。
- 服务端重启会丢失在线连接判定，所有设备先显示离线，重新鉴权连接后再上线，不凭数据库 lastSeen 宣称在线。

## 6. 系统启动与使用记录

### 6.1 存储与会话状态

DP SQLite 中保存：`bootEpochs`、`usageSessions`、`coverageGaps`、`uploadOutbox`、`commandReceipts`、`upgradeJobs`。SQLite schema 有显式迁移版本，未知版本和损坏报错，不清库自愈。短事务完成，不跨网络持锁。

系统启动状态保存 boot count、首次观察的墙钟及 elapsedRealtime，估算系统启动时刻并标记来源/时钟质量；不能把开机广播收到时间当真实启动时间，也不把 App 进程重启当系统重启。boot count 不可读时标记未知，不能据此确认远程重启。

```text
未开始
  ├─ 解锁/锁屏消失且可交互 → 开始会话
  └─ 无锁屏验证且进入可交互 → 开始会话
进行中
  ├─ 再次收到解锁/亮屏 → 不重复开始
  ├─ 退出可交互状态 → 完成会话
  └─ 系统重启或覆盖缺失 → 保留不完整记录，尝试补查
```

本期“息屏”用系统退出可交互状态识别，不把 AOD 当使用，不以每次触摸计时；实机验证普通锁屏/息屏动作与此状态的一致性。仅锁屏显示但仍可交互时不擅自提前结束已开始会话。首次观察时手机已经可用但缺少开始事件，记录缺开始，不能用服务启动时间冒充解锁时间。

完整实时会话使用同一系统启动内的 elapsedRealtime 差值计时，保存原始墙钟端点、单调端点和时钟质量；时间被修改时仍保持非负实际时长。跨重启不相减，不以检测时刻补造息屏。后台收到了非交互事件却没有开始，只产生缺开始记录。关键事件先本地事务保存，再异步上报。

### 6.2 可选历史补查

新增 `PACKAGE_USAGE_STATS` 声明及设置页授权入口；DO 不视为自动获得该特殊权限。只处理屏幕可交互/不可交互、锁屏显示/隐藏、系统中断相关事件，不持久保存或上报应用前后台包名事件。`USER_UNLOCKED` 仅触发解锁后恢复，不能视为每一次用户解锁。

UsageStats 仅保留有限历史，首次解锁前查询可能不可用，见 [查询限制](https://developer.android.com/reference/android/app/usage/UsageStatsManager#queryEvents(long,%20long)) 与 [事件定义](https://developer.android.com/reference/android/app/usage/UsageEvents.Event)。拒绝授权、空查询或查询失败均不能当作整段时间无人使用。

记录实时监测覆盖区间与缺口；重新绑定服务、获得权限、首次解锁时查询有界缺口及短重叠窗口。恢复工作分批进行，保存查询游标。实时和历史会话须按同一 boot、时间区间与事件顺序匹配，已有实时记录优先保留；只有唯一匹配且端点可靠时补齐原记录，不生成一条重叠的已完成副本。含歧义或时间跳变的重叠窗口标注覆盖不明，不拼接猜测。

每条会话具有稳定 sessionId 和递增 recordVersion；服务端按 `(deviceId,sessionId)` 幂等 upsert，旧版本不能覆盖修正记录。缺口也有稳定 ID，可被可靠历史证据修复。服务端提交成功后确认已保存 ID/版本，本地据此移出上报队列，不删除90天查询数据。过期记录不因未上传而无限保留。

### 6.3 日期、合计与保留

时间显示及按日查询采用 Asia/Shanghai。完整会话跨午夜时按与每个上海自然日的交集分摊时长；墙钟跳变时以开始锚点和可靠单调时长形成连续统计区间，标记校时影响，不用负墙钟差计算时长。历史记录只能依据系统事件墙钟重建时，保留 `HISTORY_ESTIMATED` 来源；不可靠则按不完整处理。

网页展示完整时长合计、不完整条数和监测缺口；进行中会话单独显示，未完成或缺端点的未知时长不混入“完整合计”。以日期结束早于上海当天减90天的记录为过期；恰为90天边界保留。跨边界会话保留窗口内贡献。服务端每日及启动时清理；设备在启动、记录和同步批次时限频清理，避免新增精确清理闹钟。此机制仅针对新统计存储，不改变旧管控日志的清理契约。

## 7. 应用目录与界面

设备复用 AppCatalog，上传管理范围内的名称、包名、安装状态、系统应用标识及保护原因，不上传应用使用行为或图标文件。目录上传带 snapshotId，分页接收完成后才事务切换当前目录，避免中途失败将剩余应用误报卸载。隐藏和卸载黑名单记录沿用本机规则；查询异常保留上次快照并标记陈旧。

```text
登录
 └─ 设备列表：型号/设备ID、在线状态、最近联系、App版本、同步结果
     └─ 设备详情
         ├─ 配置：总开关、应用搜索/黑名单、共用周表、保存/执行结果
         ├─ 使用：最近系统启动、日期、会话明细、合计与缺失提示
         └─ 维护：选择版本升级、在线重启（二次确认）、任务结果
版本：上传 APK → 校验结果 → 已发布版本 → 选择设备升级
```

网页不提供密码文件管理、任意包操作、退管或远程 shell。浏览器只访问同源 API，不能直接访问手机。网页草稿与服务端结果区分；明确保存才产生新配置。设备状态由服务端推送给网页或在页面可见时低频刷新，具体呈现由实现者选择，不能用陈旧在线标记允许离线重启。

App 设置页显示固定地址（只读）、设备ID、最近连接/同步结果和补查权限状态，保留既有管理入口认证及主题 token 约定；不新增本机断开或解绑开关。

## 8. APK 发布与自更新

### 8.1 发布校验

服务端只接收管理员上传的单 APK 文件，首版上限100 MiB；流式写临时文件，避免加载整个文件到内存。采用固定版本 Android build-tools 的 `apksigner verify` 和 `aapt2 dump` 读取并校验包名、versionCode、versionName、minSdk 和签名；以参数数组调用工具、限制执行时间，不能拼 shell 命令。验证成功后按 SHA-256 内容地址保存并事务建立版本记录，失败清理本次临时文件。

发布对象只允许 `com.buddydeus.androidmanager`，记录签名证书集合、hash、大小与最低系统版本；不接受管理员填写的摘要代替文件计算。API 不允许提交任意公网下载 URL。安装包只能经鉴权同源端点下载；文件名不作为路径依据。

### 8.2 安装状态机

```text
QUEUED（可离线等待） → DOWNLOADING → VERIFIED → INSTALLING
                                               ├─ 成功/自身升级后核验 → SUCCEEDED
                                               ├─ 系统拒绝 → FAILED
                                               └─ 结果丢失且无法确认 → UNKNOWN
```

每台设备同时只执行一个升级任务，重复任务 ID 不重复安装；另一升级任务在前一任务结束后处理。下载不持协调器锁，不影响本地管控。下载失败可重新下载同一对象，使用临时文件原子完成，不无限积累坏文件。

安装前再次检查设备身份、DO、存储、包名、minSdk、versionCode 高于当前版本、SHA-256/大小和与当前 APK 相同的签名集合；首版不支持签名轮换或降级。PackageManager 解析元数据后仍以 PackageInstaller 的最终签名校验为准，不把自行解析元数据当作完整密码学验证。哈希、签名、包名或兼容性校验失败为明确终止结果，不当作临时网络错误无限重试。

通过 PackageInstaller Session 完整写入 APK；创建 sessionId 与任务状态先持久化再 commit，安装结果接收器使用受限显式 IntentSender 并校验 sessionId/jobId，按目标 API 要求设置可变 PendingIntent 以接收系统填入的结果字段。支持的版本请求无需用户操作；若 ROM 返回 `STATUS_PENDING_USER_ACTION`，显示“无法自动安装”，不伪装为成功或静默改成需要用户现场确认的流程。DO 自动安装的能力依据见[专用设备安装文档](https://developer.android.com/work/dpc/dedicated-devices/cookbook)。

自更新可能终止旧进程；`MY_PACKAGE_REPLACED`、开机和服务恢复均检查持久任务、现装包名/签名/versionCode 及 PackageInstaller 会话结果。仅提交安装不算成功；目标版本已实际安装后才回报成功，版本不一致且无可恢复会话则记录失败或未知，不反复提交安装。

服务器保存结果直到设备确认收到其回执确认；进程中断可重发同一结果。系统版本已经高于目标时，待执行任务标记已被更新版本替代，不做降级；不得宣称旧任务确实安装过。

### 8.3 签名与现装设备

当前仓库 release 未配置正式签名，不能承诺现有 debug 安装可直接升级到不同签名的 release。实现提供外部 keystore/密码注入模板，不提交签名私钥、不自动生成生产身份；模拟器用同一测试签名验证两个递增版本。生产升级须使用与现装版本匹配的签名，签名不符时明确阻塞，不自动卸载、清数据或退管。测试构建使用隔离服务的临时注册凭据；生产分发构建缺少注册或签名材料时明确失败，不内置可通用于生产的默认凭据。

## 9. 仅在线整机重启

“在线”同时要求当前鉴权 WSS 会话存在且心跳未过期。网页二次确认后，API 在发送瞬间再次检查，离线直接拒绝。重启记录可持久化用于结果查询，但**不进入断线重发队列**。

```text
网页确认 → 服务端检查实时连接 → 保存 commandId 与 connectionId
 → 本连接通知设备（10秒有效）
 → 设备校验、持久去重 → 在本连接请求执行许可
 → 服务端复核在线/有效期并一次性放行
 → 设备串行入口再次校验 → 先写 ATTEMPTED → DPM.reboot()
```

命令绑定当前连接、当前 boot、随机 ID 和基于连接单调时间的短有效期；不能在新连接或新系统启动下恢复执行。执行许可请求和响应也不跨断线重试。API 发出之后恰好掉线属于“未送达/未知”，不能当作可以等到下次上线的命令。

重复消息只返回已有状态；同一 commandId 在调用前已经持久标记 ATTEMPTED，即使此后崩溃也不重试系统调用。这样选择“至多调用一次”，不宣称系统调用与落盘具有原子性：落盘后、调用前崩溃可能没有重启，显示未知，管理员可重新发起新的命令。

无 DO、通话中、正在安装或其他系统拒绝明确返回失败；不自动排队等待通话结束或升级结束。DPM 在通话中可能抛错，见[重启接口](https://developer.android.com/reference/android/app/admin/DevicePolicyManager#reboot(android.content.ComponentName))。

记录发出、设备接受、调用失败/已尝试、回连观察到后续系统启动等阶段；调用返回或连接断开均不等于重启成功。回连后比较可信 boot count 与命令前值，显示“已观察到后续启动”；无可靠证据显示“结果未知”，不能声称观察到新启动就证明没有其他原因引起重启。旧命令永远只查询结果，不重新执行。

## 10. API 与数据契约

所有 API 使用 `/api/v1`，结构化错误带 errorCode、message、requestId；协议或存储未知版本报错，不以空数据成功响应。body、字符串、数组及分页均限长；普通 JSON 1 MiB、单批最多200条记录，上传 APK 独立限制。无隐式可信客户端字段。

| API 组 | 鉴权 | 职责 |
| --- | --- | --- |
| `POST /admin/login`、`POST /admin/logout` | 登录/管理员会话 | 唯一管理员会话 |
| `GET /admin/devices[/:id]` | 管理员 | 设备与同步、执行结果 |
| `GET/PUT /admin/devices/:id/config` | 管理员 | 查看和保存完整配置 |
| `GET /admin/devices/:id/apps`、`usage` | 管理员 | 应用目录、使用明细及合计 |
| `POST /admin/releases`、`GET /admin/releases` | 管理员 | 上传校验与版本列表 |
| `POST /admin/devices/:id/upgrades`、`reboot` | 管理员 + CSRF | 升级/在线重启 |
| `POST /device/challenges`、`register` | 接入凭据 + 挑战签名 | 自动注册/恢复响应 |
| `POST /device/sync` | 设备 token | 候选比较、配置与当前任务同步 |
| `POST /device/status`、`apps`、`usage`、`results` | 设备 token | 状态、目录、幂等记录和结果 |
| `GET /device/time`、`releases/:id/apk` | 设备 token | 时间校准、获授权任务的 APK |
| `WSS /device/channel` | 设备 token | 心跳、版本通知、连接内命令/许可 |

设备 token 通过 Authorization 或首个限时认证帧传递，不放 URL 查询参数；服务端从认证结果取得 deviceId，不信任 body 中宣称的设备归属。设备只能下载分配给自己的发布包。网页 API 不接受设备 token 替代管理员会话。

服务端主要表：`admins / sessions / devices / device_credentials / config_mutations / device_configs / app_snapshots / usage_sessions / coverage_gaps / releases / upgrade_jobs / command_receipts / notification_outbox`。配置、当前版本指针和通知意图同事务保存；大文件最终发布由内容 hash 与数据库引用对齐，恢复时清理无引用的本次上传临时对象，不删除已发布包。

使用 SQL 参数绑定，所有唯一性靠数据库约束兜底。数据库短事务，分页读取，统计按设备与日期索引；写繁忙返回可重试的明确错误，不能假装已保存。schema 迁移在启动前顺序执行，失败停止服务并保留数据库。

## 11. Docker 与运维交付

Docker Compose 提供 `ams` 与可选同源 TLS 代理。容器内 Fastify 同时提供编译后的网页静态资源和 API，SQLite 与 APK 分别挂载到本机持久目录；服务以非 root 用户运行，健康检查区分进程存活与数据库可读。

- 默认生产入口为 `https://ams.opt.work`。提供 Caddy 代理配置；如已有反向代理，则只接入本机发布端口，不要求改动其他站点。证书签发需要正确 DNS 和80/443端口，不能凭域名已提供推断这些条件已满足。
- 多阶段镜像构建网页/API，运行镜像只携带必要产物、APK校验工具及运行库；Node、系统镜像、build-tools、npm 依赖锁定版本。注册凭据和管理员初始化材料由部署环境注入，示例文件只含占位符。
- `GET /health/live` 与 `/health/ready` 不泄露设备和配置；只信任所配置代理转发头。SQLite 保持单实例，不把 Compose replica 数改大来扩容。
- 备份使用 SQLite 一致性备份接口或停服复制，包含已引用 APK、数据库及部署秘密；不能只复制活动 WAL 模式下的主数据库文件。恢复后设备重连，未发送的重启命令不得重放。
- README 记录建库、管理员初始化、构建地址及接入凭据注入、启动、备份恢复、签名更新和日志排错命令。实际服务器访问、TLS 和生产签名尚未提供，作为部署前提，不影响本地实现与模拟器验收。
